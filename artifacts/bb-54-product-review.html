1 · Outcome

The shared plugin execution boundary now measures combined UTF-8 stdout and stderr from one exported 1,048,576-byte constant. Results at or below the ceiling are preserved. Results above it discard both streams and return a typed plugin_cli_output_too_large error with the limit and per-stream byte counts.

Tasks list operations now issue bounded SQLite queries with limit + 1, deterministic tuple ordering, opaque base64url cursors, and a query fingerprint. Cursors are deliberately conservative: any task-list-relevant mutation increments a database revision, so continuing from an old snapshot fails explicitly instead of skipping or duplicating records.

2 · The bounded data contract

  1. The CLI sends a plugin invocation to the real server and receives a typed execution result.
  2. The server measures complete UTF-8 streams. Above 1 MiB it returns only a structured error; it never sends a truncated success.
  3. Tasks accepts --limit 1…500 and an opaque --cursor; the default page is 100.
  4. SQLite applies filters, sort keys, tuple cursor predicates, and LIMIT in one bounded query.
  5. A continuation is valid only for the same filter/sort fingerprint and unchanged list revision.
Observed live: exactly 1,048,576 payload bytes arrive intact in both human and JSON paths. At 1,048,577 bytes, implicit and explicit plugin commands exit 1 with the same atomic structured error.

6 · Initial finding, fix, and revalidation

BB54-QA-001 · Blocking during the initial pass. The live server returned the full exact-limit body, but the CLI process exited after writing and only 65,536 bytes reached a redirected pipe. That was silent success truncation.

The initial pass was closed and recorded before implementation changed. The CLI proxy was then fixed to await both stream write callbacks before returning its exit code. This directly addresses callers that terminate the process immediately after command completion.

Resolved and reverified:

  • Human exact-limit payload: 1,048,576 / 1,048,576 bytes preserved.
  • JSON exact-limit payload: valid JSON and 1,048,576 / 1,048,576 bytes preserved.
  • Human, JSON, direct, and explicit over-limit cases: exit 1, typed atomic error, no payload leakage.
  • Full post-fix CLI suite: 335/335 passing.

7 · Remaining risk and deliberate decisions

Cursor invalidation is intentionally conservative: any list-relevant mutation stales existing cursors, even if a sophisticated snapshot system might have permitted some continuations. The trade-off is explicit retry over invisible data loss or duplication. UI helpers restart at the beginning only when callers initiate a new load; the CLI/API surface returns the error to the caller.

Compatibility list helpers may traverse several 500-row pages for internal views that require a complete project dataset. Individual database and RPC operations remain bounded, but extremely large projects still require proportionally more requests and client memory to render the complete board. That preserves existing UI semantics while removing unbounded single-query/output behavior.

No unresolved BB-54 product defect remains from the live evidence pass. The only broader-suite anomaly is the unrelated install-machine fixture noted above.
