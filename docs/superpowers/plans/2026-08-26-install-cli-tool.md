# Install CLI Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the desktop app's own bundled `bb` CLI on the user's shell `PATH`, so the `bb` they type is the `bb` their app runs.

**Architecture:** Three layers. A wrapper script shipped *inside* the macOS bundle that self-locates and execs the app's Electron as node (`layer 1`). A generated wrapper in `~/.bb/bin`, rewritten on every app launch, that points at layer 1 on macOS and at the recorded `$APPIMAGE` on Linux (`layer 2`, the only thing a user puts on `PATH`). A settings row plus a `bb install-cli` command that report and repair it (`layer 3`). Everything is gated on `app.isPackaged`.

**Tech Stack:** TypeScript, Electron, electron-builder, commander, React, vitest, zod, Turbo/pnpm workspaces.

**Spec:** `docs/superpowers/specs/2026-08-25-install-cli-tool-design.md`

## Global Constraints

- **Platforms: darwin and linux only.** Windows is out of scope and cannot be in scope. Never add a Windows branch.
- **Channel command names:** stable installs `bb`, nightly installs `bb-nightly`, unpackaged dev installs **nothing**. Copy these strings verbatim.
- **`bb-dev` is out of scope.** It was deliberately cut from v1. Do not add it.
- **`~/.bb/bin` is anchored to `$HOME`**, always `join(homedir(), ".bb", "bin")`. Never derive it from the configured data directory.
- **No privilege escalation, ever.** Never write outside `~/.bb/bin` and the app's own bundle. No `sudo`, no `osascript ... with administrator privileges`.
- **Never overwrite a foreign file.** Every file this feature writes carries the exact marker line `# bb-managed: generated by the bb desktop app. Safe to delete.` as line 2. A file at a target path without that marker is left alone and reported.
- **Build/typecheck through Turbo only:** `pnpm exec turbo run <task> --filter=<pkg>`. Never `pnpm --filter X test` or raw `tsc --noEmit`.
- **`HOST_DAEMON_PROTOCOL_VERSION`:** this feature adds no server↔daemon wire fields, so no bump is required. If a task finds itself changing a host RPC payload, stop: that is a sign the work drifted across the boundary.
- **Agent-authored PRs and issues** end with the line `> AGENT GENERATED`.
- Do not hand-edit Drizzle snapshots (none are touched here).

## Task Ordering

Tasks 1-3 are the mechanism and can be verified without any UI. Task 4 is the CLI surface. Task 5 is the settings row. Task 6 is documentation. Tasks 1 and 2 are the ones that must land together for anything to work on macOS; task 3 makes Linux work.

```ts
/**
 * Shell text for the two wrappers this feature writes.
 *
 * Kept as pure string generation with no filesystem or Electron dependency so
 * both the launch-time refresh and the `bb install-cli` command can produce
 * byte-identical output, and so the shapes can be asserted in a plain unit
 * test rather than only in a packaged smoke run.
 */

/**
 * Line 2 of every file this feature writes. A target path holding a file
 * without this line belongs to someone else and is never overwritten.
 */
export const BB_CLI_WRAPPER_MARKER =
  "# bb-managed: generated by the bb desktop app. Safe to delete.";

/** Path to the bundled CLI, relative to a bundle's resources directory. */
export const BB_CLI_BUNDLE_RELATIVE_CLI_PATH =
  "app.asar.unpacked/node_modules/bb-app/host-daemon/dist/bb";

export type BbCliWrapperTarget =
  | {
      kind: "macos-bundle";
      /** Bundle root, e.g. /Applications/bb.app. Named in the diagnostic. */
      appBundlePath: string;
      /** The layer-1 wrapper inside that bundle. */
      wrapperPath: string;
    }
  | {
      kind: "linux-appimage";
      /** Recorded from process.env.APPIMAGE at launch. */
      appImagePath: string;
      bootstrapPath: string;
    };

interface CreateBundleCliWrapperScriptArgs {
  commandName: string;
  /** electron-builder's productName, e.g. "bb" or "bb Nightly". */
  macExecutableName: string;
}

interface CreateHomeCliWrapperScriptArgs {
  commandName: string;
  target: BbCliWrapperTarget;
}

/**
 * Single-quote a value for POSIX sh. Paths here come from Electron rather than
 * from user input, but bundle names contain spaces as a matter of course and a
 * home directory can contain anything.
 */
function shellQuote(value: string): string {
  return `'${value.replaceAll("'", `'\\''`)}'`;
}

/**
 * Layer 1: ships inside the macOS bundle at Contents/Resources/bin/<name>.
 *
 * Self-locates via $0, so it needs no recorded path and no refresh: it moves
 * with the app. This is the single place that knows the bundle-internal
 * layout, which is what lets a months-old layer-2 wrapper keep working after
 * the layout changes.
 *
 * The symlink walk is hand-rolled because macOS ships the BSD realpath(1),
 * which has not always been present. VS Code hand-rolls it in code.sh for the
 * same reason, and so does this repo's bin/bb.
 */
export function createBundleCliWrapperScript(
  args: CreateBundleCliWrapperScriptArgs,
): string {
  return `#!/bin/sh
${BB_CLI_WRAPPER_MARKER}
# ${args.commandName}: run this bundle's bb CLI.
set -e

SELF="$0"
while [ -L "$SELF" ]; do
  LINK=$(readlink "$SELF")
  case "$LINK" in
    /*) SELF="$LINK" ;;
    *) SELF="$(dirname -- "$SELF")/$LINK" ;;
  esac
done

# <bundle>/Contents/Resources/bin/<name> -> <bundle>
BIN_DIR=$(CDPATH= cd -- "$(dirname -- "$SELF")" && pwd)
RESOURCES_DIR=$(CDPATH= cd -- "$BIN_DIR/.." && pwd)
APP=$(CDPATH= cd -- "$RESOURCES_DIR/../.." && pwd)

# Electron prints a node_main.cc warning to stderr on every invocation when
# NODE_OPTIONS is set. Stash rather than discard so the CLI can re-apply it to
# node children it spawns.
if [ -n "\${NODE_OPTIONS:-}" ]; then
  BB_NODE_OPTIONS="$NODE_OPTIONS"
  export BB_NODE_OPTIONS
  unset NODE_OPTIONS
fi

exec env ELECTRON_RUN_AS_NODE=1 \\
  "$APP/Contents/MacOS/${args.macExecutableName}" \\
  "$RESOURCES_DIR/${BB_CLI_BUNDLE_RELATIVE_CLI_PATH}" "$@"
`;
}

/**
 * Layer 2: written to ~/.bb/bin/<name> on every launch.
 *
 * A generated wrapper rather than a symlink on both platforms. A dangling
 * symlink reports "command not found" in zsh and bash (verified), which is
 * misleading because the file is present. The wrapper names the real cause and
 * exits 127. Using a wrapper on both platforms also collapses generation,
 * refresh, and the diagnostic into one code path.
 */
export function createHomeCliWrapperScript(
  args: CreateHomeCliWrapperScriptArgs,
): string {
  const header = `#!/bin/sh
${BB_CLI_WRAPPER_MARKER}
# ${args.commandName}: rewritten by the bb desktop app on every launch.
set -e
`;

  if (args.target.kind === "macos-bundle") {
    return `${header}
WRAPPER=${shellQuote(args.target.wrapperPath)}

if [ ! -x "$WRAPPER" ]; then
  echo "${args.commandName}: the bb app is no longer installed at ${args.target.appBundlePath}" >&2
  echo "${args.commandName}: reinstall it, or remove this file" >&2
  exit 127
fi

exec "$WRAPPER" "$@"
`;
  }

  return `${header}
APPIMG=${shellQuote(args.target.appImagePath)}
BOOTSTRAP=${shellQuote(args.target.bootstrapPath)}

if [ ! -x "$APPIMG" ]; then
  echo "${args.commandName}: the bb AppImage is no longer at ${args.target.appImagePath}" >&2
  echo "${args.commandName}: move it back and relaunch bb, or remove this file" >&2
  exit 127
fi
if [ ! -f "$BOOTSTRAP" ]; then
  echo "${args.commandName}: missing bootstrap at ${args.target.bootstrapPath}" >&2
  echo "${args.commandName}: relaunch bb to rewrite it" >&2
  exit 127
fi

if [ -n "\${NODE_OPTIONS:-}" ]; then
  BB_NODE_OPTIONS="$NODE_OPTIONS"
  export BB_NODE_OPTIONS
  unset NODE_OPTIONS
fi

exec env ELECTRON_RUN_AS_NODE=1 "$APPIMG" "$BOOTSTRAP" "$@"
`;
}

/**
 * Linux only. An AppImage self-mounts at a different ephemeral path each
 * launch, so no path inside it is stable enough to record. The wrapper records
 * the stable $APPIMAGE file; this bootstrap runs *inside* the mount and reads
 * $APPDIR to find the CLI. Both variables were verified reaching the Node
 * process through AppRun.
 */
export function createAppImageBootstrapScript(): string {
  return `${BB_CLI_WRAPPER_MARKER.replace("#", "//")}
import { join } from "node:path";

const appDir = process.env.APPDIR;
if (appDir === undefined || appDir.length === 0) {
  console.error("bb: APPDIR is unset, so the bundled CLI cannot be located.");
  process.exit(127);
}

await import(
  join(appDir, "resources/${BB_CLI_BUNDLE_RELATIVE_CLI_PATH}")
);
`;
}
```

```ts
import { chmod, mkdir, readFile, writeFile } from "node:fs/promises";
import { dirname, join } from "node:path";
import {
  BB_CLI_WRAPPER_MARKER,
  createAppImageBootstrapScript,
  createHomeCliWrapperScript,
  type BbCliWrapperTarget,
} from "./cli-wrapper-script.js";

/**
 * The ~/.bb/bin refresh.
 *
 * This is the only path a user ever puts on PATH, so it must stay valid across
 * install location, channel, and app moves. It is rewritten on every launch,
 * which is what makes moving, renaming, or auto-updating the app self-healing.
 */

/**
 * Channel command names. Stable is `bb`, nightly is `bb-nightly`, matching the
 * Linux executable policy in desktop-release-channel.mjs: a shared name would
 * let one channel shadow the other on PATH, and the two are meant to be
 * installed side by side.
 */
const COMMAND_NAME_BY_PRODUCT_NAME: Readonly<Record<string, string>> = {
  bb: "bb",
  "bb Nightly": "bb-nightly",
};

const APPIMAGE_BOOTSTRAP_FILE_NAME = "bb-bootstrap.mjs";
const WRAPPER_MODE = 0o755;

export type BbCliLinkStatus =
  | { kind: "written"; path: string }
  | { kind: "unchanged"; path: string }
  | { kind: "foreign-file"; path: string }
  | { kind: "failed"; message: string };

export interface RefreshHomeCliWrapperArgs {
  commandName: string;
  homeDir: string;
  logger: { warn(message: string): void };
  target: BbCliWrapperTarget;
}

interface ResolveCliCommandNameArgs {
  productName: string;
}

interface ResolveHomeCliBinDirArgs {
  homeDir: string;
}

interface ResolveCliWrapperTargetArgs {
  /** From resolveCliCommandName; the wrapper is named for the channel. */
  commandName: string;
  env: NodeJS.ProcessEnv;
  homeDir: string;
  platform: NodeJS.Platform;
  resourcesPath: string;
}

export function resolveCliCommandName(args: ResolveCliCommandNameArgs): string {
  return COMMAND_NAME_BY_PRODUCT_NAME[args.productName] ?? "bb";
}

/**
 * Anchored to $HOME, never to the configured data directory. The PATH line a
 * user adds by hand has to be a fixed, predictable string that survives a
 * data-directory change.
 */
export function resolveHomeCliBinDir(args: ResolveHomeCliBinDirArgs): string {
  return join(args.homeDir, ".bb", "bin");
}

/**
 * What ~/.bb/bin should point at for the app currently running.
 *
 * Returns null when there is nothing stable to record: a Linux build outside an
 * AppImage has no $APPIMAGE, and an unsupported platform has no design.
 */
export function resolveCliWrapperTarget(
  args: ResolveCliWrapperTargetArgs,
): BbCliWrapperTarget | null {
  if (args.platform === "darwin") {
    // <bundle>/Contents/Resources -> <bundle>
    const appBundlePath = dirname(dirname(args.resourcesPath));
    return {
      kind: "macos-bundle",
      appBundlePath,
      wrapperPath: join(args.resourcesPath, "bin", args.commandName),
    };
  }

  if (args.platform !== "linux") {
    return null;
  }

  const appImagePath = args.env.APPIMAGE?.trim() ?? "";
  if (appImagePath.length === 0) {
    return null;
  }

  return {
    kind: "linux-appimage",
    appImagePath,
    bootstrapPath: join(
      resolveHomeCliBinDir({ homeDir: args.homeDir }),
      APPIMAGE_BOOTSTRAP_FILE_NAME,
    ),
  };
}

/**
 * True when the file at `path` is one of ours, or absent.
 *
 * Anything else belongs to Homebrew, npm, or the user, and is never
 * overwritten. A read failure counts as foreign: refusing to write is the safe
 * direction.
 */
async function isOursOrAbsent(path: string): Promise<boolean> {
  try {
    return (await readFile(path, "utf8")).includes(BB_CLI_WRAPPER_MARKER);
  } catch (error) {
    return (error as NodeJS.ErrnoException).code === "ENOENT";
  }
}

async function writeExecutable(path: string, contents: string): Promise<void> {
  await writeFile(path, contents);
  await chmod(path, WRAPPER_MODE);
}

/**
 * Rewrite ~/.bb/bin/<name> for the running app. Called on every launch: the
 * cost is one read plus an occasional rewrite, and every-launch is what makes
 * a moved or updated app self-heal without the user doing anything.
 */
export async function refreshHomeCliWrapper(
  args: RefreshHomeCliWrapperArgs,
): Promise<BbCliLinkStatus> {
  const binDir = resolveHomeCliBinDir({ homeDir: args.homeDir });
  const wrapperPath = join(binDir, args.commandName);

  try {
    if (!(await isOursOrAbsent(wrapperPath))) {
      args.logger.warn(
        `Left ${wrapperPath} alone: it was not written by bb. Remove it to let bb manage this command.`,
      );
      return { kind: "foreign-file", path: wrapperPath };
    }

    const desired = createHomeCliWrapperScript({
      commandName: args.commandName,
      target: args.target,
    });
    await mkdir(binDir, { recursive: true });

    if (args.target.kind === "linux-appimage") {
      await writeFile(
        args.target.bootstrapPath,
        createAppImageBootstrapScript(),
      );
    }

    let current: string | null = null;
    try {
      current = await readFile(wrapperPath, "utf8");
    } catch {
      current = null;
    }

    if (current === desired) {
      return { kind: "unchanged", path: wrapperPath };
    }

    await writeExecutable(wrapperPath, desired);
    return { kind: "written", path: wrapperPath };
  } catch (error) {
    const message = error instanceof Error ? error.message : String(error);
    args.logger.warn(`Could not refresh ${wrapperPath}: ${message}`);
    return { kind: "failed", message };
  }
}
```

```ts
import { join, sep } from "node:path";
import type { Command } from "commander";

/**
 * `bb install-cli`: put this app's bb on the user's PATH.
 *
 * Not circular. An agent running inside bb already has bb on PATH via
 * runtime-shell-env.ts, so this is exactly the command an agent can run to fix
 * the user's outside-the-app case, without a settings window.
 *
 * This CLI ships inside the daemon bundle and cannot import @bb/desktop, so it
 * re-derives the same paths and marker. The strings below are pinned by tests
 * on both sides.
 */

const WRAPPER_MARKER =
  "# bb-managed: generated by the bb desktop app. Safe to delete.";
const BUNDLE_CLI_SUFFIX = join(
  "Contents",
  "Resources",
  "app.asar.unpacked",
  "node_modules",
  "bb-app",
  "host-daemon",
  "dist",
  "bb",
);

interface ResolveBundleFromCliPathArgs {
  cliPath: string;
  platform: NodeJS.Platform;
}

interface ResolvedBundle {
  appBundlePath: string;
  commandName: string;
  wrapperPath: string;
}

/**
 * Locate the containing .app from the running CLI's own path.
 *
 * macOS only: a Linux AppImage mounts at a different ephemeral path each
 * launch, so ~/.bb/bin has to be written by the app from $APPIMAGE at launch
 * rather than by the CLI from where it happens to be running.
 */
export function resolveBundleFromCliPath(
  args: ResolveBundleFromCliPathArgs,
): ResolvedBundle | null {
  if (args.platform !== "darwin") {
    return null;
  }
  if (!args.cliPath.endsWith(`${sep}${BUNDLE_CLI_SUFFIX}`)) {
    return null;
  }

  const appBundlePath = args.cliPath.slice(
    0,
    args.cliPath.length - BUNDLE_CLI_SUFFIX.length - 1,
  );
  if (!appBundlePath.endsWith(".app")) {
    return null;
  }

  const commandName = appBundlePath.endsWith("bb Nightly.app")
    ? "bb-nightly"
    : "bb";

  return {
    appBundlePath,
    commandName,
    wrapperPath: join(appBundlePath, "Contents", "Resources", "bin", commandName),
  };
}

function createHomeWrapper(bundle: ResolvedBundle): string {
  return `#!/bin/sh
${WRAPPER_MARKER}
# ${bundle.commandName}: rewritten by the bb desktop app on every launch.
set -e

WRAPPER='${bundle.wrapperPath.replaceAll("'", `'\\''`)}'

if [ ! -x "$WRAPPER" ]; then
  echo "${bundle.commandName}: the bb app is no longer installed at ${bundle.appBundlePath}" >&2
  echo "${bundle.commandName}: reinstall it, or remove this file" >&2
  exit 127
fi

exec "$WRAPPER" "$@"
`;
}

async function isOursOrAbsent(path: string): Promise<boolean> {
  try {
    return (await readFile(path, "utf8")).includes(WRAPPER_MARKER);
  } catch (error) {
    return (error as NodeJS.ErrnoException).code === "ENOENT";
  }
}

export function registerInstallCliCommand(program: Command): void {
  program
    .command("install-cli")
    .description("Install this app's bb command into ~/.bb/bin")
    .action(
      action(async () => {
        const bundle = resolveBundleFromCliPath({
          cliPath: process.argv[1] ?? "",
          platform: process.platform,
        });

        if (bundle === null) {
          if (process.platform === "linux") {
            throw new Error(
              "On Linux the bb command is written by the desktop app at launch. Start the bb AppImage once, then add ~/.bb/bin to PATH.",
            );
          }
          throw new Error(
            "This bb is not running from a packaged bb.app, so there is no app bundle to link. Install the desktop app, or use the npm-global bb you already have on PATH.",
          );
        }

        const binDir = join(homedir(), ".bb", "bin");
        const wrapperPath = join(binDir, bundle.commandName);

        if (!(await isOursOrAbsent(wrapperPath))) {
          throw new Error(
            `${wrapperPath} was not written by bb, so it was left alone. Remove it and re-run to let bb manage this command.`,
          );
        }

        await mkdir(binDir, { recursive: true });
        await writeFile(wrapperPath, createHomeWrapper(bundle));
        await chmod(wrapperPath, 0o755);

        console.log(`Installed ${bundle.commandName} at ${wrapperPath}`);
        if (!(process.env.PATH ?? "").split(":").includes(binDir)) {
          console.log(`Add it to your PATH:\n\n  export PATH="$HOME/.bb/bin:$PATH"\n`);
        }
      }),
    );
}
```

```ts
import { accessSync, constants, statSync } from "node:fs";
import { delimiter, join } from "node:path";
import type { BbDesktopCliCommandStatus } from "@bb/desktop-contract";
import { resolveHomeCliBinDir } from "./cli-link.js";

/**
 * What the settings row reports.
 *
 * The PATH read needs no new probe: main.ts already calls
 * ensurePackagedUserShellPath at startup on packaged builds, which runs the
 * login shell and assigns the result to process.env.PATH. By the time an IPC
 * handler runs, process.env.PATH is the user's login PATH.
 */

interface ResolveCliCommandStatusArgs {
  commandName: string;
  homeDir: string;
  path: string;
}

function isExecutableFile(path: string): boolean {
  try {
    if (!statSync(path).isFile()) return false;
    accessSync(path, constants.X_OK);
    return true;
  } catch {
    return false;
  }
}

export function resolveCliCommandStatus(
  args: ResolveCliCommandStatusArgs,
): BbDesktopCliCommandStatus {
  const binDir = resolveHomeCliBinDir({ homeDir: args.homeDir });
  const wrapperPath = join(binDir, args.commandName);
  // An empty PATH entry means the current directory, not our bin dir.
  const entries = args.path
    .split(delimiter)
    .filter((entry) => entry.length > 0);
  const matches = entries
    .map((entry) => join(entry, args.commandName))
    .filter(isExecutableFile);

  return {
    binDir,
    commandName: args.commandName,
    matches,
    onPath: entries.includes(binDir),
    ownEntryWins: matches[0] === wrapperPath,
    wrapperInstalled: isExecutableFile(wrapperPath),
  };
}
```

```tsx
import { useCallback, useEffect, useState } from "react";
import type { BbDesktopCliCommandStatus } from "@bb/desktop-contract";
import { Button } from "@bb/shared-ui/button";
import {
  SettingsSection,
  SettingsWithControl,
} from "@/components/ui/settings-section";
import { appToast } from "@/components/ui/app-toast";
import { getBbDesktopInfo } from "@/lib/bb-desktop";

/**
 * Put this app's own bb on the user's PATH, and show when something else would
 * win. An npm-global or Homebrew bb shadowing ours is the "silently runs the
 * wrong bb" failure the feature exists to prevent, so it is displayed rather
 * than documented away.
 *
 * Gated on the desktop bridge exposing `cliCommand`, the feature-detect idiom
 * used elsewhere in bb-desktop.ts, so the web build and older desktop shells
 * render nothing.
 */
function statusBadge(status: BbDesktopCliCommandStatus | null): string | null {
  if (status === null) return null;
  if (!status.wrapperInstalled) return "Not installed";
  if (!status.onPath) return "Not on PATH";
  if (!status.ownEntryWins) return "Shadowed";
  return "Installed";
}

function description(status: BbDesktopCliCommandStatus | null): string {
  if (status === null) {
    return "Install this app's bb command so the bb you type is the bb this app runs.";
  }
  if (!status.wrapperInstalled) {
    return `Install \`${status.commandName}\` into ${status.binDir} so the bb you type is the bb this app runs.`;
  }
  if (!status.onPath) {
    return `Installed at ${status.binDir}. Add it to your shell profile: export PATH="$HOME/.bb/bin:$PATH"`;
  }
  if (!status.ownEntryWins) {
    return `Another ${status.commandName} comes first on PATH: ${status.matches[0]}. Move ${status.binDir} ahead of it.`;
  }
  return `\`${status.commandName}\` resolves to this app, from ${status.binDir}.`;
}

export function CliCommandSettingsSection() {
  const api = getBbDesktopInfo()?.cliCommand;
  const [status, setStatus] = useState<BbDesktopCliCommandStatus | null>(null);
  const [pending, setPending] = useState(false);
  const badge = statusBadge(status);

  useEffect(() => {
    if (api === undefined) return;
    void api.getStatus().then(setStatus);
  }, [api]);

  const install = useCallback(() => {
    if (api === undefined) return;
    setPending(true);
    api
      .install()
      .then((next) => {
        setStatus(next);
        appToast.success(`Installed ${next.commandName} in ${next.binDir}`);
      })
      .catch((error: unknown) => {
        appToast.error(
          error instanceof Error ? error.message : "Could not install the command",
        );
      })
      .finally(() => setPending(false));
  }, [api]);

  if (api === undefined) {
    return null;
  }

  return (
    <SettingsSection title="Command line">
      <SettingsWithControl
        label="bb command"
        {...(badge === null ? {} : { labelBadge: badge })}
        description={description(status)}
      >
        <Button
          type="button"
          variant="outline"
          size="sm"
          disabled={pending}
          onClick={install}
          aria-label="Install the bb command"
        >
          {pending ? "Installing…" : status?.wrapperInstalled ? "Repair" : "Install"}
        </Button>
      </SettingsWithControl>
    </SettingsSection>
  );
}
```

- [ ] **Step 5: Document the Linux runtime prerequisites**

The spec's Risk 4 asks that the `libfuse2` and Chromium shared-library failures
be surfaced rather than discovered. Runtime detection is not implementable from
the app: by the time the settings row can run, the app is already running, so
both prerequisites are satisfied by construction. The failure appears only when
the wrapper is invoked from a *different* environment (a container, a headless
server), which the app cannot observe, and the wrapper cannot report either
because it `exec`s. Documentation is the honest surface.

Add to `docs/configuration.md`, under the `~/.bb/bin` entry:

```markdown
On Linux the command re-invokes the AppImage, so it inherits the AppImage's
runtime requirements. A machine that runs the bb desktop app already has them;
a container or headless server may not:

- **`libfuse2`.** AppImage type 2 needs it, and Ubuntu 24.04 ships only fuse3.
  A present `/dev/fuse` and `fusermount3` are not sufficient. Without it the

  whole image on every invocation.
- **Chromium's shared libraries.** Even with `ELECTRON_RUN_AS_NODE`, the
  Electron binary still dynamically links the GUI stack, and a minimal system
  fails with `error while loading shared libraries: libnspr4.so`. "It's just
  Node" is not true on Linux.
```
