# Change Log

История изменений файлов треда в правой панели: список всех правок агента по
ходам, с патчами и метками времени — без прокрутки чата.

Плагин выключен по умолчанию. Включите его в Settings → Installed plugins или:

```powershell
bb plugin enable change-log
```

## Как открыть

В треде нажмите **+** в правой панели и выберите **Changes** в списке Actions.
Откроется вкладка с историей изменений этого треда.

## Что показывает

- Записи в хронологическом порядке, сгруппированные по ходам (новые сверху).
  В заголовке хода — номер, выдержка из промпта, время начала и длительность
  работы агента.
- Каждая запись: действие (создан, изменён, удалён, переименован), путь,
  `+n −m`, время. Клик по записи раскрывает unified-дифф; для workspace-файла
  доступно **Open file**.
- Последовательные правки одного файла внутри одного хода схлопываются в одну
  запись с бейджем `N edits`: суммируются `+/−`, показывается самый ранний
  доступный патч. Если провайдер сообщил правку без текста диффа (бывает у Pi
  для повторных записей), запись показывает `changed`, а не `+0 −0`.
- **Open file** показывается только для путей внутри workspace треда; для
  абсолютных путей (вне корня) кнопка скрыта.
- Переключатели в шапке:
  - **By turn / By file** — группировка по ходам (по умолчанию) или по файлам;
    в режиме по файлам в заголовке группы итоговые `+n −m` файла.
  - **Child threads** — включать правки дочерних тредов (по умолчанию включено);
    такие записи помечены бейджем `child`.
- Фильтр по подстроке пути, кнопка обновления и **Load older changes**, когда
  в таймлайне есть более старые страницы.
- Правки приходят в реальном времени, пока вкладка открыта; при разрыве
  соединения панель догоняет состояние.

Патчи рендерит штатный просмотрщик bb, поэтому учитываются темы и замены
diff-рендерера из других плагинов. Очень большие патчи (больше ~200 000
символов) не встраиваются — вместо них показывается пометка.

## CLI

```powershell
bb change-log list <thread-id>
bb change-log list <thread-id> --path <query>
bb change-log list <thread-id> --limit 20
bb change-log list <thread-id> --patches
bb change-log list <thread-id> --json
bb change-log list <thread-id> --json --json-patches
```

- Без `--json` печатает по строке на изменение, новые сверху.
- `--json` отдаёт тот же объект, что панель, но без патчей; добавьте
  `--json-patches`, чтобы включить их.
- `--limit` ограничивает число строк (по умолчанию 50), `--path` фильтрует по
  подстроке пути.

## SDK

Те же данные доступны из серверного кода плагина:

```ts
const timeline = await bb.sdk.threads.timeline({
  threadId,
  includeNestedRows: "true",
});
```

Каждая правка файла — строка с `kind: "work"` и `workKind: "file-change"`:
`change.path`, `change.kind`, `change.movePath`, `change.diff`,
`change.diffStats`, плюс `turnId`, `createdAt`, `status`, `approvalStatus`.
Пути релятивизованы к корню workspace треда, включая Windows-пути с прямыми
слэшами от провайдера и корень с обратными. Страница таймлайна отдаёт
`timelinePage.hasOlderRows` и `timelinePage.olderCursor` для перехода к более
старым записям.

## Разработка и проверка

```powershell
pnpm exec turbo run typecheck test --filter=bb-plugin-change-log
```

`server.ts` регистрирует RPC, realtime-сигналы и CLI; `server/` собирает и
агрегирует таймлайн; `components/` и `app.tsx` — за вкладку; `lib/` — чистая
логика группировки и форматирования времени. Тесты покрывают сбор строк,
агрегацию, пагинацию, усечение патчей, RPC, CLI и поведение панели.
