# PC Control

Встроенный плагин для работы с одним ПК: нижняя плашка CPU/RAM и панель **PC Control** с обзором ресурсов, процессами и сохранёнными программами. Те же операции доступны через `bb pc`.

Основная платформа — Windows. На macOS и Linux доступна сокращённая поддержка метрик и списка процессов. Выбора машины в плагине нет: запросы идут подключённому host-daemon сервера, либо первому зарегистрированному хосту.

## Возможности

- **Плашка CPU/RAM** обновляется каждые 2 секунды. Точка показывает свежие данные, устаревшие значения или ошибку. При ширине окна меньше 1024 px используется компактный индикатор у нижнего края, чтобы не перекрывать поле сообщения. Нажатие открывает панель на экранах треда; на экранах без такой панели открытие может быть недоступно.
- **Overview** — загрузка CPU, память и время работы. Устаревшие значения приглушаются и сохраняют время последнего измерения.
- **Processes** — имя, PID, CPU и память. Есть поиск, сортировка и ручное обновление. CPU процесса рассчитывается по разнице накопленного процессорного времени между измерениями.
- **Programs** — профили с `name`, `exe`, `args`, `cwd` и необязательным `processName`. Доступны создание, изменение, удаление, запуск, остановка и перезапуск. Остановка и перезапуск через интерфейс требуют подтверждения.

Системные метрики собираются внутри процесса через `node:os`; опрос плашки не запускает PowerShell. PowerShell вызывается при запросе списка процессов или действия над программой.

## CLI

```powershell
bb pc status
bb pc processes --sort cpu --limit 20
bb pc processes --query notepad
bb pc apps --json
bb pc start <profile>
bb pc stop <profile>
bb pc restart <profile>
```

`<profile>` — имя или ID существующего профиля. `status`, `processes` и `apps` поддерживают `--json`. Неизвестный профиль возвращает ошибку `Unknown profile`; произвольная командная строка вместо профиля не принимается.

## Профили и ограничения безопасности

Профили хранятся в пространстве плагина через `bb.storage.kv`, а не рядом с исходниками. Запросы проверяются схемами Zod; операции ОС выполняет host-daemon. Сервер отвечает за профили и маршрутизацию, но не запускает локальные программы.

- Программа получает массив аргументов без подстановки shell. Поля профиля не вставляются в текст PowerShell-команды.
- Остановка выбирает процессы, соответствующие профилю, и повторно проверяет их идентичность перед завершением. Используются `taskkill /PID <n> /T`, затем при необходимости `/F`.
- Штатное завершение ожидается до 5 секунд; вся операция ограничена 20 секундами.
- `exe` и `cwd` должны быть абсолютными существующими путями длиной не более 600 символов. На Windows нужен `.exe`.
- Не более 32 аргументов по 1024 символа без управляющих символов, 32 профилей с уникальными именами и 32 совпавших PID на профиль.
- Сбор процессов: до 500 записей, до 4 МиБ вывода, тайм-аут 15 секунд; RPC возвращает до 100 строк.
- Параллельные читатели используют общий сборщик и последнее измерение, не сбрасывая основу расчёта друг другу.

**Состояние профиля определяется в том числе по имени процесса.** Другая программа с тем же именем может считаться запущенным профилем и попасть под остановку после подтверждения. По возможности указывайте отличимый `processName` и проверяйте PID.

Для чужих повышенных процессов Windows может не дать прочитать `Path`; тогда сопоставление идёт по имени. Начальное значение CPU отображается как `—`, пока не собрано второе измерение. Запущенные программы отсоединяются; сам плагин не завершает их автоматически при отключении. Ограничения общего supervisor/Windows Job Object также действуют на его дочерние процессы.

Цвет нагрузки: обычный уровень ниже 85%, предупреждение 85–95%, критический — от 95%. Единые пороги находятся в `components/load-thresholds.ts`.

## Проверка вручную

1. Откройте тред → новую правую вкладку → **PC Control**. Проверьте плашку и обновление Overview за 2–4 секунды.
2. В Processes проверьте поиск по имени/PID, сортировку CPU/RAM и обновление только по кнопке Refresh.
3. Создайте тестовый профиль безвредной программы, например Блокнота. Проверьте запуск и появление PID; затем остановку и перезапуск с подтверждением. Не используйте для этой проверки рабочие приложения.
4. Сравните результат с `bb pc status`, `bb pc processes --limit 5` и `bb pc apps --json`.
5. На отдельном тестовом экземпляре отключите daemon: панель должна показать ошибку, а плашка — приглушённые последние значения. После восстановления дождитесь свежих метрик.
6. При ширине 800 px проверьте компактный индикатор и доступность кнопки отправки сообщения.

## Разработка

```powershell
pnpm exec turbo run typecheck test --filter=bb-plugin-pc-control
```

Тесты используют подставные сборщики, процессы и RPC-клиент; реальные пользовательские программы в них не запускаются. Основные части: `server.ts` — профили и CLI, `host.ts` — хост, `pc/metrics.ts` — метрики, `pc/process-listing.ts` — процессы, `pc/apps.ts` — запуск и остановка.
