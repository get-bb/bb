# Git Graph

Панель графа Git только для чтения: линии коммитов, ветки и теги, вложенные репозитории, состояние рабочей копии и изменения файлов. Все Git-команды выполняются на хосте выбранного проекта.

## Работа с панелью

Откройте **Git Graph** в боковой панели. При переходе из треда выбираются его проект, основной источник файлов и корневой репозиторий. В панели можно вручную переключить источник и репозиторий; активные `путь @ хост` показаны в строке инструментов.

- Обнаруживаются корневой и вложенные репозитории, worktree, submodule с файлом `.git`, а также родительский репозиторий, если папка проекта находится внутри него.
- Служебные каталоги, например `node_modules`, `.runtime`, `dist`, `build` и содержимое `.git`, пропускаются. Символические ссылки на каталоги не обходятся. Глубина, количество каталогов и время поиска ограничены.
- **Show All** объединяет HEAD и локальные ветки. Выбор нескольких веток показывает доступную из них историю.
- **Show remote branches** добавляет уже известные локальному Git remote-tracking refs и их коммиты. Плагин не выполняет fetch. Псевдонимы `refs/remotes/*/HEAD` исключаются.
- История упорядочена через `git log --date-order`: потомки раньше родителей, в остальном по дате коммита. Линия первого родителя остаётся слева.
- Поиск по сообщению коммита не учитывает регистр. Результаты отображаются без линий к отсутствующим родителям. **Refresh** перечитывает данные, **Load more** и прокрутка загружают следующие страницы.

## Граф и карточки

HEAD выделен кольцом, merge-коммиты — ореолом. Наведение подсвечивает цепочку предков; у выбранного коммита она остаётся выделенной. Ширина графа стабильна при прокрутке и может увеличиться при загрузке страницы с более широкой историей. Строки и SVG виртуализированы.

Метки различают текущую, локальную и удалённую ветку, теги и stash. Совпавшая локальная и удалённая ветка объединяются в метку вроде `main │ origin`. Длинные названия сокращаются с подсказкой, лишние метки сворачиваются в `+N`. На узкой панели последовательно скрываются колонки Author и Date.

Нажмите коммит, чтобы увидеть полный hash, автора и коммитера, даты, дерево, родителей, сообщение, refs, список изменённых файлов и diff. Родители открываются нажатием; hash можно скопировать. Слишком большой patch помечается как усечённый.

Несохранённые в Git изменения отображаются отдельной строкой **Uncommitted changes**, связанной с HEAD. Карточка показывает staged, unstaged, untracked и conflicted. Во время поиска эта строка скрыта. Из панели изменения не применяются и не откатываются.

## CLI

```powershell
bb git-graph repos --project <project-id>
bb git-graph log 5 --project <project-id>
bb git-graph show <hash> --project <project-id>
```

Подставьте ID проекта и hash коммита. `repos` принимает `--source <id>`, `log` — `--repo <path>` и `--grep <text>`, `show` — `--repo <path>`. Команды возвращают те же сведения через хост выбранного источника.

## Безопасность и пределы

- Выполняются только читающие Git-команды. `GIT_OPTIONAL_LOCKS=0` не позволяет `status` обновлять индекс; `-c core.fsmonitor=false`, `--no-ext-diff` и `--no-textconv` отключают побочные обработчики.
- Используется `execFile` с массивом аргументов, без shell; перед путями файлов ставится `--`. Пробелы, Unicode и обратные слеши в Windows-путях передаются одним аргументом.
- Сервер определяет источник по ID проекта и направляет запрос его host-daemon. Он не выполняет Git и не обращается к локальным файлам вместо хоста.
- Хост заново проверяет путь репозитория относительно корня источника; переход выше корня должен совпадать с `git rev-parse --show-toplevel`.
- Hash должен соответствовать `^[0-9a-f]{4,40}$`. Абсолютные пути файлов, обход каталогов и значения, похожие на опции, отклоняются.
- Страница содержит до 300 коммитов, статус — до 2000 записей, patch — до 1 МБ. У команд заданы тайм-ауты и пределы вывода; окна процессов скрыты.

## Разработка и проверка

```powershell
pnpm exec turbo run typecheck test --filter=bb-plugin-git-graph
```

`contract.ts` и `host-contract.ts` задают RPC; `server.ts` выбирает источник и обслуживает CLI; `host.ts` проверяет пути и вызывает Git на нужной машине. В `git/` находятся запуск, поиск репозиториев, разбор вывода и сервис. `graph/` отвечает за линии, геометрию и цвета; `components/` и `app.tsx` — за панель.

Тесты покрывают пути, вложенные репозитории, worktree/submodule, Unicode и переименования, merge-графы, ограничения, refs и безопасность аргументов. Интеграционные проверки запускают настоящий Git во временных репозиториях; без установленного Git они пропускаются.

Ручная проверка:

1. Откройте панель из тредов двух проектов и проверьте переключение проекта и хоста.
2. Проверьте корневой, вложенный и пустой репозитории, worktree и submodule.
3. Переключите локальные ветки и Show remote branches; сравните историю с `git log --date-order`.
4. Прокрутите длинную историю с merge-коммитами: колонки не должны сдвигаться, линии — проходить через чужие точки.
5. На отдельном тестовом проекте измените и проиндексируйте файлы. Счётчики должны совпасть с `git status --porcelain`, а просмотр не должен менять индекс.
6. Откройте карточку merge-коммита, родителей и diff; проверьте поиск, копирование hash, загрузку следующей страницы и узкую панель.

Галерея прототипов — внутренний инструмент разработки, не часть инструкции по эксплуатации Windows-сборки.
