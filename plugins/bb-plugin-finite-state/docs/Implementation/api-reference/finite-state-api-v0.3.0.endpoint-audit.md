# Finite State API v0.3.0 — Endpoint Surface Audit

_Audit date: 2026-06-17. Spec: Finite State Customer API **v0.3.0** (OpenAPI 3.0.3), vendored at `.claude/skills/finite-state-api/openapi.yaml`. **166 operations / 134 paths / 26 tags.** Method: 9 domain lanes cross-referenced spec ↔ current SKILL.md ↔ forge code; findings verified against source._

**Totals:** 9 lanes · 16 raw tool ideas → 10 ranked · 51 spec changes · 21 forge fixes (4 breaking/high) · 52 SKILL edits.

## Executive Summary

**Finite State API v0.3.0 audit — top-line.** All 166 operations across 26 tags were covered by the 9 lanes. The headline is a **major API surface expansion** that turns several long-standing forge "blockers" into shippable work: the entire `securityAssessment` tag (27 GET ops) and the `filesystem` family (4 ops) are **new**, and they publish — over the public customer API (`X-Authorization`, server-side fsan/org resolution) — exactly the caller-graph, symbol-import/export, ELF load-graph, kernel-config, and unpacked-rootfs data that forge's pentest reachability lane has been reconstructing locally and that `RemoteSTPClient` (qemu_static_reachability.py:1471) explicitly defers as "internal-only / Workflow 16 cross-team." **That cross-team blocker is now stale** — the data is reachable from `FiniteStateAPI`, so `FORGE_STP_BACKEND=remote` becomes viable and the LocalSTPClient firmware-walk demotes to a fallback. Second headline: a **new bulk VEX SET** endpoint (`bulkSetFindingStatusV0`, maxItems 5000, one rate-limit token per batch) **directly contradicts** the SKILL/MEMORY quirk "bulk apply does NOT exist" and obsoletes forge's per-finding `asyncio.gather` fan-out in core/vex.py — the single biggest documented operational pain point (write-token exhaustion, K8s OOM on bulk-clear). Verified live against source: the cwes path, the audit `sort`+RSQL handling, the VEX fan-out, the STP stub, and the wrong delete_folder docstring all match the audit claims. **What breaks forge:** the cwes wrapper points at a nonexistent path; `get_platform_audit` sends an unsupported `sort` param and validates a non-RSQL filter as RSQL with an `action==` example referencing a field that does not exist; the scan-status enum dropped `FAILED/RUNNING/PAUSED` and added `UPLOAD_FAILED/PENDING_UPLOAD`, which can hang the Workflow-15 scan gate; the tracker components/preview path shape in the SKILL quirk is wrong; and the raw_api tracker preflight misses the pvId-scoped path. **What is additive/doc-only:** EPSS-weighted sort keys + a new `config/scoring` family, project create/update field changes (lowercase `type`, required description, `priorities` as array), folder re-parent/description support, `includeFiles` SBOM param, and many response-shape gaps. The strategic priority is clear: **build the STP tool family and the filesystem family (they unblock the pentest program), adopt bulk VEX (token economics), then fix the breaking docs/code.** 16 tool ideas dedupe to 10 ranked tools; 21 forge fixes, 5 of them breaking-or-misleading; 52 SKILL edits.

## SKILL.md Rewrite Guidance

**Two net-new top-level sections to add.**

1. **`### Security Assessment (STP relay)`** — the largest gap. Document the whole 27-op family: base prefix `/public/v0/projects/versions/{projectVersionId}/security-assessment/`, shared params (`projectVersionId` path; optional `scanId` to override the default latest-successful-binary-scan), findings-read permission, and 'verbatim STP relay' semantics. Add a **StpRelayErrorResponse code table** (INVALID_PROJECT_VERSION_ID, INVALID_SCAN_ID, INVALID_FILE_HASH, PROJECT_VERSION_NOT_FOUND, SCAN_NOT_FOUND, **NO_FILESYSTEM_SCAN** = no completed binary scan, distinct from not-found, PATH_NOT_FOUND, FILE_NOT_FOUND, **STP_UPSTREAM_ERROR=502** = transient → retry). Call out the **three ADMIN-ONLY ops** (crypto/details, docker-image/config/raw, users → 403 + sensitive output: do not log/echo) and the **un-surfaced X-Has-More** pagination quirk (infer 'more' from a full page on the search endpoints). Document the key shapes: callgraph callers/callees (required `function[]` + optional `filePath` → target/source_function + edges[CallgraphEdge{function_name, source/target_file_path/hash, call_type ∈ direct|cross_binary|unresolved}] + has_more); has-imports/has-exports (required `import[]`/`export[]`, match_mode any|all, offset/limit → [{file_hash, file_paths, matched_imports|matched_exports}]); binaries/file-details (imports/exports/symbols/library_dependencies + SAST functions, empty without a BINARY_SAST scan); dependencies/loads + loaded-by; kernel/config. Cross-reference RemoteSTPClient as the intended consumer.

2. **`### Firmware Filesystem`** — document the 4 `projects/versions/{pvId}/filesystem/` ops (note this prefix differs from the `versions/{pvId}/` family). Hash-addressed model: `file_hash` from `/tree` is the key for overview/content/file. Two-tier permissions: **tree + overview = findings-read; content + file = org-admin VIEW_ANY_PROJECT_FILE (403 otherwise)**. Params: tree (path default /, depth 1-8, scanId); overview/file (hash + scanId); content (hash, offset default 0, maxBytes default 4096 cap 131072=128KiB, scanId). content/file return octet-stream. Note FilesystemTreeNode + FileOverviewV0 are additionalProperties:true (STP-relayed); overview.security_features = NX/PIE/RELRO/ASLR {name,enabled}.
