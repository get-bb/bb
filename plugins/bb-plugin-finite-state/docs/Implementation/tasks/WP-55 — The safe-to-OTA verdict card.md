## Context

The verdict is deterministic evidence evaluation, not a green button and not prose generated by an agent. It is version-scoped: all required requirements for the product version and every tier each requirement declares required. A run contributes evidence; one run rarely defines the whole verdict.

Evidence must bind to the current firmware digest. A result for different bytes is stale and cannot prove the current version. Safe also requires verified signed evidence; unsigned, unverifiable, or subject-mismatched proof is a gap. Gaps are inconclusive, never green.

## What to build

1. Implement one pure evaluator used by RPC, panel, card, directive, and CLI renderer. No component may reimplement verdict logic.
2. Load required requirements and required tiers from the SPEC 03 model/matrix projection for a pvId. Optional requirements/tiers appear in coverage but do not gate the verdict.
3. For each required requirement/tier, select the latest completed mapped result whose run firmware_digest equals the evaluated current digest. Ignore running, stale-digest, unmapped, and superseded evidence for proof.
4. Classify failed/error evidence on any required check as NOT_SAFE. This has precedence over gaps.
5. Classify SAFE_TO_OTA only when every required requirement/tier has a pass, there is no required fail/error, and each counted proof is covered by a verified attestation whose subject digest equals the current digest.
6. Otherwise classify INCONCLUSIVE and enumerate missing mapping, not run, running, skipped, unsigned, invalid signature, stale digest, and missing current digest separately.
7. Add a stale overlay whenever a caller asks to view a historical verdict whose evaluated digest differs from the currently mounted digest. Never relabel it as current.
8. Return the complete evidence references behind every cell: requirement ID, tier, run ID, check ID, outcome, attestation ID/verification, and timestamps.
9. Build VerdictCard with id/digest only. It self-fetches, renders verdict text plus icon/color, digest, tier coverage, requirement coverage, gaps/failures, signature identity when verified, and links to the matrix/run/evidence download.
10. Render in three-second hierarchy: verdict, firmware digest, blocking failures/gaps, coverage, signature. Do not show SAFE without the words Safe to OTA.
11. Implement a deterministic text/CLI renderer with the same evaluator result. Agent guidance later emits the card rather than paraphrasing safety.

## Interface contract

    export type OtaVerdict = "SAFE_TO_OTA" | "NOT_SAFE" | "INCONCLUSIVE";

    export type CoverageState =
      | "proven" | "failed" | "error" | "unmapped" | "not_run"
      | "running" | "skipped" | "unsigned" | "invalid_signature" | "stale_digest";

    export interface VerdictEvidence {
      requirementId: string;
      tier: MatrixTier;
      state: CoverageState;
      runId?: string;
      checkId?: string;
      outcome?: string;
      attestationVerified: boolean;
      evidenceDigest?: string;
    }

    export interface VerdictResult {
      pvId: string;
      firmwareDigest: string | null;
      currentMountedDigest: string | null;
      verdict: OtaVerdict;
      stale: boolean;
      required: number;
      proven: number;
      failed: number;
      gaps: number;
      evidence: VerdictEvidence[];
      computedAt: string;
    }

    export function evaluateOtaVerdict(input: VerdictInput): VerdictResult;
    export function getOtaVerdict(deps: VerdictDeps, pvId: string, digest?: string): Promise<VerdictResult>;
    export function renderVerdictCli(result: VerdictResult): string;

## Acceptance criteria

- [ ] One pure evaluator drives RPC, UI, and CLI.
- [ ] Verdict scope is all required requirements and required tiers for the version.
- [ ] Any required fail/error produces NOT_SAFE even when other evidence is missing.
- [ ] SAFE requires complete required coverage, matching firmware digests, and verified subject-bound attestations.
- [ ] Missing/unmapped/unrun/skipped/unsigned/invalid/stale evidence produces INCONCLUSIVE, never SAFE.
- [ ] Historical/different-digest evidence renders stale and cannot prove current bytes.
- [ ] Every verdict line links to the exact requirement/check/run evidence behind it.
- [ ] VerdictCard self-fetches by validated ID/digest and uses text/icon plus color.
- [ ] CLI output and card counts match byte-for-byte fixture expectations.

## Test plan

- evaluate.test.ts — empty model, no current digest, all pass/signed, one fail, one error, missing tier, unmapped, skipped, running, unsigned, invalid signature, stale digest, optional tier unrun, multiple runs latest selection, and failure precedence.
- query.test.ts — joins results through run digest, attestation subject match, version scope, historical digest, and corrupt/missing requirement model returns INCONCLUSIVE with MODEL_UNAVAILABLE.
- verdict-card.test.tsx — green/red/amber accessible render, digest/stale overlay, failure/gap drill-through, signature details, loading/empty/error/unconfigured states, and unknown ID.
- render-cli.test.ts — golden output for all verdicts and no ANSI-only meaning.
- Invariant/property test — evaluator never returns SAFE when any required evidence state differs from proven.

## Do not

- Do not let an agent, user, or server boolean set the verdict directly.
- Do not compute the verdict from a single run unless it truly covers every version requirement/tier.
- Do not count optional checks as required, unmapped checks as proof, or stale bytes as current.
- Do not call unsigned evidence signed, fabricate Rekor/Fulcio details, or hide gaps.
- Do not duplicate evaluator logic in React or CLI.

## Open questions

1. This WP resolves SPEC 05's scope proposal as version-scoped. If product leadership chooses run-scoped wording, it must use a different label than Safe to OTA.
2. Define whether an attestation may cover multiple result rows by requirement_ids or requires per-result binding. Default to explicit inclusion of every counted requirement/check.
3. HIL measured-value policy and Tier-4 countersignatures are future inputs; unknown formats remain inconclusive.
