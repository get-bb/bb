| What you see | Likely cause | Fix |
| --- | --- | --- |
| The skill works in one agent but not another | Each agent reads its own folders | Put it in a folder that agent reads, or in `~/.bb/skills` for every agent |
| A skill in `~/.agents/skills` is missing for Claude Code | Claude Code doesn't read `~/.agents/skills` | Use `~/.claude/skills` or `~/.bb/skills` |
| A skill in a nested folder is missing | Most agents only look one folder deep | Move its folder directly under the skills folder |
| A symlinked skill in your project is missing | The link points outside the project | Keep the target inside the repository, or use a user folder |
| Project skills are missing, user skills show | The project has no checkout on the selected machine | Pick a machine that has the project, or add the project there |
| A skill in `~/.bb/skills` is missing | Invalid `name` or `description`, or a duplicate name | [Fix the front-matter](#the-skill-is-in-the-wrong-shape) |
| The menu shows the folder name, not the skill's `name` | bb names agent skills after their folder | Rename the folder |
| Typing `/` does nothing | Nothing matches, or `/` isn't at the start of a word | Type `/` at the start of the message or after a space |
| "Failed to load commands" | bb couldn't ask the machine for its skills | See [Failed to load commands](#failed-to-load-commands) |
| The skill is in the menu, but the agent doesn't use it | The running agent started before you added it | See [The agent doesn't use the skill](#the-agent-doesnt-use-the-skill) |

## Where bb looks for skills

A skill is a folder with a `SKILL.md` in it. `~` is the home folder on the thread's machine; project folders are in the project's checkout.

| Agent | Your skills | Project skills |
| --- | --- | --- |
| Every agent | `~/.bb/skills` | `.bb/skills` |
| Claude Code | `~/.claude/skills`, and skills from Claude Code plugins you turned on | `.claude/skills`, and commands in `.claude/commands` |
| Codex | `~/.codex/skills`, `~/.agents/skills` | `.codex/skills`, `.agents/skills` |
| Pi | `~/.pi/agent/skills`, `~/.agents/skills`, and the `skills` paths in Pi's settings | `.pi/skills`, `.agents/skills` |
| Cursor | `~/.cursor/skills`, `~/.agents/skills`, `~/.claude/skills`, `~/.codex/skills` | The same folders in the project |
| opencode | `~/.claude/skills`, `~/.agents/skills`, `~/.config/opencode/skills` | `.opencode/skills`, `.claude/skills`, `.agents/skills` |

- `~/.bb/skills` is read on the bb server's machine and works with every agent on every machine.
- bb also reads `.claude/skills` and `.agents/skills` in parent folders, up to the folder that holds `.git`.
- If you set `CLAUDE_CONFIG_DIR`, `CODEX_HOME` or `PI_CODING_AGENT_DIR`, bb reads the skills folder inside it too.

**Skills** in the sidebar lists what bb found, under **My skills**; `bb skill list` does the same.

## The skill is in the wrong shape

Every skill:

- Lives at `<skills folder>/<skill name>/SKILL.md`, named exactly `SKILL.md`. Only Pi and Cursor also look in nested folders.
- Is named in the menu after its folder, not its front-matter `name`.
- In a project, may be a symlink only to a target inside the repository. Links in home folders can point anywhere. Claude Code reports the skills it loads itself, so it may still list such a link.

Skills in `~/.bb/skills` and `.bb/skills` are copied to every agent, so they also need:

- A `name` of lowercase letters, numbers and single hyphens that matches the folder name.
- A non-empty `description` of at most 1024 characters.
- No symlinks in the folder other than `SKILL.md`.
- A unique name. A project skill replaces a `~/.bb/skills` skill with the same name; two at the same level are both skipped.

```markdown title="~/.bb/skills/release-notes/SKILL.md"
---
name: release-notes
description: Write release notes from the merged pull requests since the last tag.
---
```

The server log names skipped skills: "Skipping invalid injected skill" or "Skipping colliding injected skill".

## Project skills don't show

bb reads project skills from the project's checkout on the thread's machine; with no checkout there, the menu shows only your own skills. Pick a machine that has the project. To see what the menu gets:

```bash
bb project commands <project-id> --provider claude-code --machine <machine>
```

## Failed to load commands

bb couldn't get the list, for example because the thread's machine isn't connected. Check it in **Settings → Machines**, then type `/` again; bb asks again each time.

## The agent doesn't use the skill

A running agent loads skills when it starts. Stop it with `bb thread stop <thread-id>`, then send your next message; the thread keeps its history.

Codex must also list the skill itself. If Codex doesn't know it, or it's off in Codex, bb sends your text as typed. Type `$` for a menu of skills only.

## What to send when you ask for help

- `bb --version`, the agent, and the machine's operating system.
- The full path of `SKILL.md` and `ls -la` of its folder.
- The first lines of `SKILL.md`, with its front-matter.
- `bb skill list --json` and `bb project commands <project-id> --provider <provider-id> --json`.
- The server log from `~/.bb/logs/` (desktop: **View → Local Logs**).
