Use this when you want a different model, more or less reasoning, a faster speed, or a bigger context window for a thread.

## Pick a model and reasoning level

<Tabs items={["Desktop", "CLI"]}>
<Tab value="Desktop">

1. In the composer, click the model picker, next to the **+** button. It shows the current model and reasoning level, and has a [keyboard shortcut](/docs/keyboard-shortcuts).
2. Choose the agent from the icons along the top, then a model under **Model**.
3. Choose a level under **Reasoning**.
4. If the model has faster speeds, turn on **Fast mode**, or pick one under **Speed** when there are several.

<Tab value="CLI">

```sh
bb provider models claude-code
bb thread spawn --provider claude-code --model claude-opus-5-5 --reasoning-level high "Review the open PR"
```

`--service-tier fast` picks a faster speed, and `--option <option=value>` sets a model option such as Codex's Daybreak.

</Tab>
</Tabs>

Each agent offers its own reasoning levels, and each model may offer fewer:

| Agent | Reasoning levels |
| --- | --- |
| Claude Code | Low, Medium, High, Extra High, Ultracode, Max |
| Codex | None, Low, Medium, High, Extra High, Max, Ultra |
| Pi | None, Low, Medium, High, Extra High, Max |
| ACP agents | What the agent reports |

Faster speeds cost more. To turn them off everywhere, including queued messages and automations, switch off **Allow faster service tiers** in **Settings → Providers**. The switch covers every agent.

## Change the model in a running thread

Pick a different model or reasoning level in the thread's composer; it applies from the next message. To move the conversation to a different agent, choose **Handoff to new thread** in the same menu.

From a terminal, `bb thread tell <id> --model <model> "message"` uses a model for one message, and `bb thread update <id> --model <model>` keeps it for the following turns.

## Set defaults for a project

There is no fixed default model setting. Instead, bb remembers the agent, model, reasoning level, permission mode and speed of the last thread you started from the app in each project, and new threads in that project start with them.

- **Default agent:** in **Settings → Providers**, open an agent's **⋯** menu and check **Default**. bb uses it in projects where you haven't picked one yet.
- **Child threads** start with their parent's model and reasoning level when they use the same agent.
- **From the CLI,** `bb thread spawn` without `--provider` or `--model` uses the project's remembered choice, then the agent's own default.

## Get 1M context

The context window size belongs to the model and your account, not to bb.

- **Claude Code** decides which models get a 1M-token window for your account. When it lists a separate 1M version of a model, the picker shows it as its own entry ending in **(1M)**.
- To turn the 1M window off for Claude Code threads, switch on **Disable 1M context** in **Settings → Plugins → Claude Code provider**.
- Threads routed through the [Account Pooler](/docs/use-several-accounts) keep the 1M window.

To see a thread's window, hover the ring in the composer. It shows the tokens used out of the window, and turns amber at 75% and red at 90%. When a thread is getting full, type `/compact` (or run `bb thread compact <id>`) to summarize its history, on agents that support it.

## If a model is missing

The model list comes from the agent installed on the machine the thread runs on, not from bb. bb rereads it in the background, and again when a machine connects.

1. Update the agent on that machine. New models usually need a newer Claude Code, Codex, Pi or ACP agent.
2. Check what the agent reports on that machine: `bb provider models <provider-id> --machine <machine>`.
3. If the list says it couldn't load models, the agent isn't installed or signed in on that machine. See [Claude Code](/docs/claude-code), [Codex](/docs/codex), [Pi](/docs/pi) or [ACP agents](/docs/add-acp-agents).

To use a model ID an agent accepts but doesn't list, add it to `customModels` in `~/.bb/config.json`; see [Run local models](/docs/add-acp-agents#run-local-models).

## Check it worked

The model picker shows the model, reasoning level and speed you chose, and the thread's next reply uses them.
