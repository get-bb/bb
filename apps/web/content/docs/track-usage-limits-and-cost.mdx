bb adds no charge of its own; the limits are the ones each provider reports.

## See your usage limits

<Tabs items={["Desktop", "CLI"]}>
<Tab value="Desktop">

1. Click **Provider usage** at the bottom of the sidebar.
2. Pick a provider tab, or **All** for every account.

Each window shows a bar, the percent used and the time until it resets. **Reload provider usage** fetches fresh numbers.

<Screenshot
  src="/docs-images/track-usage-limits-and-cost/usage-card"
  alt="The Provider usage card above the sidebar footer shows each account with a bar, the percent used and the time until reset for every usage window."
  width={272}
  height={262}
/>

The same numbers, full size, are in **Settings → Plugins → Provider usage** under **Usage limits**.

</Tab>
<Tab value="CLI">

```sh
bb settings usage --machine <machine> --refresh
```

This shows one machine's signed-in agents. For Account Pooler accounts, use `bb pool status`.

</Tab>
</Tabs>

| Agent | What it shows |
| --- | --- |
| Claude Code | Five-hour and weekly windows, plus weekly windows per model family |
| Codex | Codex windows, for ChatGPT accounts only |
| Cursor | Plan usage and on-demand spend |
| opencode | OpenCode Go's five-hour, weekly and monthly windows, when Go is set up on that machine |
| Account Pooler | Every pooled Claude and Codex account |
| Pi and other agents | Nothing. "Usage not reported" never means zero use. |

Usage is per machine, since each machine has its own logins. With the [Account Pooler](/docs/use-several-accounts) on, the card shows the pool's accounts; switch to one machine with the card's machine menu or **Usage source** in settings.

To hide the card, right-click it and choose **Hide**. **Settings → Appearance** orders the sidebar footer actions.

## See a thread's context and cost

Hover the ring in a thread's composer for the percent of the context window used, tokens used, and **Session cost** when the agent reports one. **Show details** breaks down the context.

Claude Code, Codex and Pi report context use. ACP agents report context and cost only if they support it. Subscription agents show no per-thread dollar cost.

## Spend less of your limits

| Do this | How |
| --- | --- |
| Lower reasoning or a smaller model, especially for child threads | See [Choose a model, reasoning and context size](/docs/choose-a-model-reasoning-and-context-size) |
| Turn off faster speeds (Fast and Ultrafast cost more per token) | Switch off **Allow faster service tiers** in **Settings → Providers** |
| Compact long threads | `/compact` before continuing |
| Compact idle threads before resuming | Turn on **Compact before resuming expired sessions** in **Settings → Experiments**. Threads over 100k tokens with an expired prompt cache then offer **Compact first**. |
| Add another account | The [Account Pooler](/docs/use-several-accounts), with the Provider retry plugin resuming threads when a limit resets |

## Check it worked

The card lists each signed-in account with its windows and reset times. An account that says to sign in again has an expired login on that machine or in the Account Pooler.

## Related troubleshooting

- [Use several accounts](/docs/use-several-accounts#if-no-account-is-eligible): every pooled account is at its limit.
- [Codex](/docs/codex#check-it-worked): Codex limits are missing.
