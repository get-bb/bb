## Watch children and answer their questions

- In **Active child threads**, each child is marked **Working** or **Needs input**; children with questions come first.
- Click a child's question to answer it without opening the child.
- Click a child to open it, [steer it](/docs/send-steer-and-queue-messages) with a message, or take over.

The parent's **Info** tab lists all its **Child threads**, finished ones too.

## Choose what reaches the parent

When a child finishes a turn, fails, is interrupted or gets stuck, bb tells the parent's agent and adds a row such as "… finished" to the parent's timeline. A finished child's final answer goes to the parent's agent.

**Notify parent** on each child sets which of these reach the parent:

| Option | The parent hears about |
| --- | --- |
| **Auto** (default) | Every finished turn, failure and blocker |
| **When stuck** | Only failures, interruptions and blockers; no final answer |
| **Off** | Nothing |

## Follow children from the parent's agent

Agents use the same commands you can run:

```sh
bb thread list --parent-thread <parent-id>
bb thread wait <child-id>
bb thread output <child-id>
bb thread tell <child-id> "Use the existing validation helper"
bb thread tell <child-id> --mode queue "Also update the README when you're done"
```

`bb thread wait` blocks until the child is idle. `bb thread tell` steers the current turn; `--mode queue` waits until it ends.

## Check it worked

- The child's **Info** tab shows your **Notify parent** choice, and `bb thread show <child-id>` prints it under `Parent notifications:`.
- With **Auto**, a "… finished" row appears in the parent's timeline when the child finishes.

## Related troubleshooting

- **The parent never hears from a child:** check the child's **Info** tab has a **Parent** and **Notify parent** isn't **Off**. [Forks](/docs/fork-hand-off-or-switch-models#fork-a-thread) never notify the thread they came from.
- **A chatty child wakes the parent every turn:** set it to **When stuck**.
- **A child waits on an [approval](/docs/choose-a-permission-mode#answer-an-approval):** look for **Needs input** in the parent's **Active child threads**, or open the child.
