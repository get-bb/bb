| You want to | Use | What you get |
| --- | --- | --- |
| Use another model from the same agent | The model picker | The same thread, with the new model |
| Use a different agent | **Handoff to new thread** | A new thread linking to this one |
| Try another direction from an earlier answer | **Fork into new thread** | A new thread with the conversation so far |
| Ask a quick question about one answer | **Reply in side chat** | A small chat in a panel |

## Switch the model in a thread

1. Click the model name in the box at the bottom of the thread.
2. Pick another [model or reasoning level](/docs/choose-a-model-reasoning-and-context-size) from the same agent.
3. Send your next message.

A thread stays with one agent; picking another agent starts a handoff.

```sh
bb thread tell <thread-id> "Keep going" --model <model> --reasoning-level <level>
bb thread update <thread-id> --model <model>
```

## Hand off to another agent

1. Click the model name and choose **Handoff to new thread**, or pick a model from another agent.
2. Pick the agent and model.
3. Type what the new thread should do and send it.

The new thread uses the same project and folder. Its first message links to the old thread; the conversation isn't copied. [Archive](/docs/organize-and-archive-threads) the old thread when you're done.

From a terminal, spawn a thread that mentions the old one. `bb thread show <thread-id> --json` prints the IDs:

```sh
bb thread spawn --project <project-id> --environment <environment-id> --provider codex --prompt "Continue from @thread:<thread-id> and finish the migration"
```

## Fork a thread

1. Hover over an agent's answer and open **Message actions**.
2. Choose **Fork into new thread**.

<Screenshot
  src="/docs-images/fork-hand-off-or-switch-models/fork-menu"
  alt="The Message actions menu under an agent's answer is open, with Fork into new thread outlined."
  width={512}
  height={203}
/>

The fork has the conversation up to that answer and the same agent, model and folder. The original doesn't change.

Claude Code, Codex and Pi fork from any answer; some agents fork only from the latest answer.

```sh
bb thread fork <thread-id> --prompt "Try the same fix with a migration instead"
```

Add `--new-environment worktree` to keep the fork's changes apart from the original's.

## Ask a side question

1. Hover over a message and choose **Reply in side chat**. Select text first to ask about only that part.
2. Ask in the panel that opens.
3. Choose **Send to main thread** on an answer to bring it back.

A side chat is a fork kept out of the sidebar and archived with its thread. It has no CLI commands.

## Check it worked

- After a switch, the model picker shows the new model.
- After a handoff or fork, the new thread opens in the sidebar.

## Related troubleshooting

- **Fork into new thread** is missing: the agent [can't fork](/docs/agent-feature-support#threads-and-the-composer), the thread is archived, or it has no folder.
- "can only fork at the end of a session, not from an earlier point in it": fork from the latest answer.
- A model is missing from the picker: see [A model is missing from the model picker](/docs/a-model-is-missing-from-the-model-picker).
