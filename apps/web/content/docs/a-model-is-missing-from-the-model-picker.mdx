"Where is the newest model?" or "Why can I only get 200K context?" bb doesn't keep its own list of models. The picker shows the models the agent's CLI reports on the machine selected for the thread, so a model appears in bb once that CLI knows about it.

| What you see | Likely cause | Fix |
| --- | --- | --- |
| A newly released model is missing | The agent's CLI on that machine is older than the model | Update the CLI, then open the picker again |
| The model is in your terminal but not in bb | The thread is set to another machine, where the CLI is older or signed in differently | Pick the machine in the composer, or update the CLI on it |
| A Claude thread is limited to 200K context | The model or your login doesn't get the 1M window, **Disable 1M context** is on, or a custom base URL limits it | See [1M context is missing](#1m-context-is-missing) |
| "Could not load models for Claude Code." | bb couldn't get the list from the agent | Read the reason under it and see [the reasons below](#could-not-load-models-for-claude-code) |
| "No models available" | The agent answered with an empty list | Update the CLI and check its sign-in |
| Reasoning shows only Medium for an ACP agent's model | Older bb versions guessed a single level for models they hadn't checked | Update bb, then pick the model again |
| A model the agent accepts isn't listed at all | The agent doesn't list it | Add it as a custom model |

## A new model is missing

1. Update the agent's CLI on the machine the thread runs on. **Settings → Updates** shows each machine's CLIs under **Provider CLIs** and offers an update when one is available. You can also update it from a terminal, for example by running `claude update` for Claude Code.
2. Open the model picker again. bb keeps the last list it got and checks the agent again in the background when the list is more than a minute old, so the new model can take one more opening of the picker to appear.

To see exactly what bb gets from the agent, run `bb provider models <provider-id>`, for example `bb provider models claude-code`. Add `--machine <machine>` to ask a specific machine.

Some models are listed under **More models** at the bottom of the picker. For Claude Code, that's where its aliases are, each with "alias" after its name.

## 1M context is missing

Whether a Claude model gets the 1M-token context window depends on the model, your Claude Code version and your login. Claude Code decides this, not bb. Some models come with the 1M window, and some are offered as a separate entry with "(1M)" after the name, for example "Opus 5.5 (1M)". If a thread is limited to 200K:

- **Update Claude Code**, as above.
- **Check Disable 1M context.** Open **Settings**, then **Claude Code provider** in the sidebar's **Plugins** group. When **Disable 1M context** is on, Claude Code threads don't use the 1M window. Or run `bb plugin config provider-claude-code set disable1MContext false`.
- **Check for a custom base URL.** Claude Code limits Opus to a 200K context window when `ANTHROPIC_BASE_URL` points it at another server. The Account Pooler plugin keeps the 1M window for its own accounts.

The context ring in a thread shows the window Claude Code reports for the thread's model. If the picker has a "(1M)" entry for your model, pick it to use the larger window.

## Could not load models for Claude Code.

The picker says "Could not load models for" and the agent's name, with the reason under it. Long reasons are folded behind **Show details**. A new thread can't be sent while this error shows.

| Reason | What it means | Fix |
| --- | --- | --- |
| CLI not found | The agent's CLI isn't installed on that machine, or bb can't find it | See [An agent won't sign in or can't be found](/docs/an-agent-wont-sign-in-or-cant-be-found#claude-code-not-installed) |
| Not signed in | The CLI on that machine has no working login | See [Not signed in](/docs/an-agent-wont-sign-in-or-cant-be-found#not-signed-in) |
| Timed out | The agent didn't answer in time | Open the picker again. ACP agents get 30 seconds to list their models |
| Provider plugin failed to load | The agent's plugin is off or failed to start | Check it in **Settings → Installed plugins** |
| Any other text | The agent's own error message | Read the message; it usually says what's wrong |

bb remembers a failure for 30 seconds, so wait a moment after fixing the cause before opening the picker again.

## No models available

The agent answered, but its list was empty. Update the CLI and check that it's signed in. For Pi, the list comes from the model providers you signed in to inside Pi, so sign in to at least one.

## Reasoning shows only Medium

Older versions of bb gave an ACP agent's models a single Medium level when bb hadn't had time to check them. Update bb. bb now checks a model's reasoning levels when you pick it, and hides the reasoning control for a model that doesn't report any.

To see the levels bb found, run `bb provider models <provider-id> --selected-model <model>`.

## Add a model the agent doesn't list

If an agent accepts a model but doesn't list it, add it to `customModels` in `~/.bb/config.json`, then run `npx bb-app config refresh` or restart bb:

```json title="~/.bb/config.json"
{
  "customModels": [
    { "providerId": "claude-code", "model": "claude-example-preview" }
  ]
}
```

Custom models appear after the agent's own models. Claude Code and Codex accept models they don't list; an ACP agent can reject one when the thread starts. **Streamer mode** in **Settings → General** hides custom models from every picker.

## What to send when you ask for help

- Your bb version (`bb --version`) and operating system.
- The agent's CLI version on the thread's machine, for example `claude --version`.
- The output of `bb provider models <provider-id> --json` for that machine.
- The model you expected and where you saw it, for example in your terminal or the provider's release notes.
- The exact error text in the picker, including the reason under it.
- Whether you use the Account Pooler or set `ANTHROPIC_BASE_URL`.
