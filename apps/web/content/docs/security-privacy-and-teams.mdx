bb runs your agents on your own machines, as your user. That makes it powerful and means the security question is simple: whoever can reach your bb server, or install a plugin in it, can do what you can do on that computer.

This page covers what bb can reach, who can reach bb, what leaves your machine, and what that means for sharing a server with a team.

## What bb can reach

| Who | Can reach | Limited by |
| --- | --- | --- |
| **Agents** | Files and commands on the machine that runs the thread | The thread's permission mode, and the machine's permission limit |
| **Plugins** | Everything the bb server can, including all local bb data and other plugins' secrets | Nothing. Plugins are full-trust code; install only ones you trust |
| **Host daemon** on each machine | Runs agents and commands there for the server | It only takes work from the server it was added to |

Each thread has a permission mode:

| Mode | What the agent may do |
| --- | --- |
| **Accept Edits** | Edits inside the workspace automatically; anything beyond it asks you first |
| **Approve for me** | The same workspace sandbox, with requests reviewed automatically; high-risk actions can still come back to you |
| **Full Access** | No sandbox and no approvals; the agent can run anything on your machine |

Each machine also has a **Permission limit**, set on its page in **Settings → Machines**. Threads on that machine never run above it, whatever mode they ask for. Child threads don't inherit a cap from their parent; only the machine limit applies.

## Who can reach bb

- **On your machine:** the bb server listens on `127.0.0.1` (port 38886) by default. Its local API has no password by design: any program on that machine can drive bb. bb rejects requests from web pages on other sites, so a website you visit can't.
- **From your other devices:** use bb Connect or a private network such as Tailscale. bb Connect only lets in the bb account that owns the server. Phones pair with a code that lasts 10 minutes and works once, and you can revoke a device from your getbb.app dashboard.
- **Never on an open network:** `--server-bind-host 0.0.0.0` exposes the unauthenticated API to everyone who can reach that address. Use it only behind a network boundary you trust, never on the public internet.
- **Other machines:** a machine you add gets its own credential, and can't change machine settings such as the permission limit.

## What leaves your machine

- **Your code and conversations** go only to the agent providers you use, such as Anthropic or OpenAI, under your own account.
- **Usage data:** bb sends anonymous usage data, such as app starts, setup progress and feature use. Turn it off in **Settings → General → Privacy & diagnostics → Share anonymous usage data**, or set `BB_TELEMETRY=false` in the server's environment. The iOS and Android apps send no analytics.
- **bb Connect traffic** passes through the relay while in flight. TLS protects it from the network, but the relay terminates TLS, so it is not end-to-end encrypted. The relay doesn't record or store it.
- **Push notifications** pass through Apple or Google with a short preview of the message, so they aren't end-to-end encrypted either.

bb keeps its data in `~/.bb` on the server's machine. Values you add in **Settings → Environment variables** are stored encrypted.

## Teams

bb has no user accounts, roles or per-person permissions. Everyone who can open a bb server has the same full access to it, its machines and its plugins, and plugins are installed for the whole server.

| If you want to | Do this |
| --- | --- |
| Work alone across your devices | One server, reached through bb Connect or Tailscale |
| Share with a small team you fully trust | One server on a private network everyone can reach. Agree on permission modes, since every thread runs as the server's user |
| Keep people or clients separate | A separate bb server for each |
