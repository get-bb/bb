| Event | Notification |
| --- | --- |
| The agent asks a question or needs an approval | The question, or what it wants, such as "Approve command: …" or "Review the plan before the agent continues" |
| The thread fails | "The thread hit an error" |
| The agent finishes its turn | "Finished and waiting for you" |

The title is the thread's name; click to open the thread. bb skips threads you've read, including the one you're looking at, and archived threads. Notifications come from the bundled **Push notifications** plugin, on by default.

## Turn on notifications on this device

<Tabs items={["Desktop", "Web", "Phone"]}>
<Tab value="Desktop">

1. Open **Settings** and choose **Push notifications** under **Plugins**.
2. Under **This desktop app**, click **Allow notifications**, then **Send test notification**.

They show while the app runs. The dock or taskbar icon counts threads that need input.

</Tab>
<Tab value="Web">

1. Open **Settings** and choose **Push notifications** under **Plugins**.
2. Under **This browser**, click **Allow notifications**, accept the prompt, then **Send test notification**.

They show only while bb is open in a tab, over HTTPS or `localhost`. Each browser asks separately.

</Tab>
<Tab value="Phone">

The bb app for iOS or Android gets them even when closed. Pair it with your server first (see [Use bb on your phone](/docs/use-bb-on-your-phone)).

1. When asked "Get notified when a thread needs you?", tap **Turn on notifications**.
2. To change it later: **Settings** → **This device** → **Notifications**, then **Push notifications** per server.

The server must be reachable over HTTPS or [bb connect](/docs/set-up-remote-access#bb-connect). Each server's status says why when it can't register.

</Tab>
</Tabs>

## Choose what you're notified about

On the **Push notifications** settings page:

| Setting | Does |
| --- | --- |
| **Mobile**, **Web**, **Desktop notifications** | Turn each channel on or off for the whole server |
| **Default notifications** | **All activity**, **Needs input only** (no finished turns) or **Muted** |
| **Child thread notifications** | Level for [child threads](/docs/follow-child-threads-from-the-parent); default **Needs input only** |

For one thread, open its sidebar menu → **Notifications** and pick **Same as default**, **All activity**, **Needs input only** or **Muted**. A child can't notify more than its parent allows.

```sh
bb push-notifications thread <thread-id> --level muted
bb plugin config push-notifications set defaultLevel input-only
```

## See what needs you in the sidebar

| Icon | Means |
| --- | --- |
| Question mark | Needs your input |
| Red cross | Failed |
| Dot | Unread reply |

**Mark read** and **Mark unread** are in the thread's menu.

## Check it worked

- **Send test notification** shows "bb notifications are working".
- `bb push-notifications status` lists the channels and devices that will be notified.

## Related troubleshooting

- "Notifications are blocked": allow bb in your browser or system settings, then return.
- None for a thread you had open: bb marked it read.
- None on your phone: [the server's status](/docs/use-bb-on-your-phone#3-turn-on-notifications) should read "On · registered with this server", and **Mobile notifications** be on.
- "Push notifications plugin is disabled on this server": [turn it on](/docs/find-and-install-plugins#manage-installed-plugins) in **Settings → Installed plugins**.
