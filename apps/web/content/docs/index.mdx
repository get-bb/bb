Your code, agents and threads stay on machines you control. The desktop app, web app, phone app, `bb` CLI and API all drive the same bb, so anything you do in the app, you or an agent can script.

<Video src="/docs-videos/index/what-is-bb" title="A tour of bb's threads, projects, agents, machines and plugins" width={1280} height={720} />

## How bb fits together

| Term | What it is |
| --- | --- |
| **Thread** | One conversation with one agent about one piece of work. Watch it, message it, fork it, or hand it off. |
| **Child thread** | A thread started by another thread. A parent splits a task, hands each part to a child, and hears back when each finishes. |
| **Project** | A repository bb works in. |
| **Environment** | Where a thread's code lives: by default its own Git worktree. It can also be your project checkout or a personal workspace. |
| **Agent** | The coding agent CLI that does the work. Settings calls these **Providers**. |
| **Machine and server** | The server keeps your threads; a host daemon on each machine runs agents there. One server can use several machines. |
| **Plugins and skills** | Plugins add features to bb itself; skills are instructions your agents can load. |

## Ask your agent about bb

Agents in bb have the `bb` command. Ask one how to do something; it looks it up with `bb guide` and can do it for you.
