| What you see | Likely cause | Fix |
| --- | --- | --- |
| "Your bb is offline" at your getbb.app address | bb's machine is asleep, offline, or bb isn't running | [Wake the machine and start bb](#your-bb-is-offline) |
| "bb connect hit a temporary problem" | A short error in bb connect's service | Wait; the page retries by itself |
| "This is …'s bb" with a sign-in button | This browser isn't signed in as the server's owner | Sign in with the account that owns the server |
| **Reconnecting…** in **Settings → bb connect** | The tunnel dropped and bb is retrying | [Read the details under it](#reconnecting) |
| **Remote access is off** | Remote access was turned off | Click **Turn on**, or run `bb connect on` |
| "That code is invalid or has expired." | Pairing codes last 10 minutes and work once | Get a new code from the getbb.app dashboard |
| "Device limit reached" on your phone | The account has its maximum of paired devices | Revoke a device in the getbb.app dashboard |
| "Could not sign in" on your phone | The phone's pairing was revoked or expired | Pair the phone again with a new code |
| Remote access drops often, local is fine | A busy server, sleep, or an unstable network | See [It keeps dropping](#it-keeps-dropping) |

## Your bb is offline

Local access on bb's machine keeps working. The page retries every few seconds.

1. Wake the machine and check that bb is running.
2. On macOS and Windows, turn on the **Keep Awake** plugin; `bb keep-awake status` checks it.
3. If it stays offline, run `bb connect status` on that machine, or open **Settings → bb connect**, and find the message below.

## bb connect hit a temporary problem

A request failed in bb connect's service before it reached your bb. If it lasts more than a few minutes while `bb connect status` shows `connected`, ask for help.

## This is your bb, but it asks you to sign in

Only the getbb.app account that owns a bb can open its address. Sign in with it in this browser.

## Reconnecting…

The text next to **Reconnecting…** says why; open **Show details** if it's cut off.

| Details | Fix |
| --- | --- |
| "this bb isn't signed in to a bb account — sign in to turn remote access back on" | Sign in from **Settings → bb connect**, or run `bb account login` |
| "the gate refused this bb's server credential (HTTP 401)" or "(HTTP 403)" | Run `bb account login` |
| "another bb connected with this server's identity and took over bb connect" | Stop the other bb, for example a copy of this data folder on another machine |
| "can't reach getbb.app — handshake timed out", "connection closed", "connection refused" or "host not found" | Check the machine can open getbb.app, and allow WebSocket connections to it through firewalls and proxies |
| "can't read this bb's server credential" | Turn on **bb account** in **Settings → Installed plugins** |

### The bb account plugin is off. Turn it on under Plugins, then try again.

bb connect signs in through the **bb account** plugin. Turn it on in **Settings → Installed plugins** or with `bb plugin enable bb-account`, then sign in again.

## That code is invalid or has expired.

Also "That code has expired." or "That code was already used." Get a new code from the getbb.app dashboard, then enter it or run `bb connect --code <code>`.

## Device limit reached

From **Settings → Mobile** it reads "Your getbb.app account has reached its machine limit." Revoke an unused device in the getbb.app dashboard, then pair again.

## Could not sign in

The phone's pairing was revoked or expired. Pair it again with a new code. "Cannot reach this server" instead means the server or its tunnel is down; see [Your bb is offline](#your-bb-is-offline).

## It keeps dropping

Common causes:

- **The machine sleeps or changes networks.** Use **Keep Awake** and a stable connection.
- **The server is overloaded**, for example by many agents on a small machine. See [bb is slow or uses a lot of memory](/docs/bb-is-slow-or-uses-a-lot-of-memory).
- **A proxy or firewall closes long-lived connections.** Allow WebSocket traffic to getbb.app.

Requests in flight when it drops fail; reload the page. On a private network you control, Tailscale works without bb connect:

```bash
tailscale serve --bg --https=443 http://127.0.0.1:38886
npx bb-app config set BB_APP_URL https://<machine>.<tailnet>.ts.net
```

Your Tailscale access rules then decide who reaches bb; don't expose it with Funnel or to the public internet.

## What to send when you ask for help

- `bb --version` and the operating system of bb's machine.
- `bb connect status --json` and `bb account status`.
- The exact message, where you saw it, and when.
- `bb plugin logs connect -n 200`, which shows each connection attempt and why it closed.
- Whether local access worked meanwhile, and whether the machine slept or changed networks.
